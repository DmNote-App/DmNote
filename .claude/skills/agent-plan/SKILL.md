# 계획 독립 검증

1. 메인이 codebase-memory 그래프 도구로 관련 코드를 파악한다. `search_graph`로 탐색, `trace_call_path`로 콜체인·영향 범위, `get_architecture`로 구조. 그래프에 없는 문자열·설정값만 Read/Grep으로 보완한다.
2. 초안 계획을 세운 뒤 `Agent`(general-purpose, `model` 생략해 메인 상속, 백그라운드)에게 **사실 정보만** 넘겨 독립 검증을 받는다. 메인의 결론은 넘기지 않는다 (anchoring 방지). 변경 범위가 크고 Rust·React가 얽혀 있으면 초안 없이 동시에 독립 분석시킨다.
3. 피드백 중 정확성·누락 범위·더 나은 접근만 반영한다. 방어 코드 추가 같은 오버엔지니어링 제안과 프로젝트 컨벤션에 대한 지적은 생략한다.
4. 서브에이전트가 실패하면 그 사실을 명시하고 메인 단독으로 계획한다. 후속 질문은 `SendMessage`로 같은 에이전트에 한다.

## 서브에이전트 프롬프트

```
당신은 DmNote(Tauri: Rust + React)의 독립 설계 검증자입니다. 파일은 직접 읽고, 코드는 수정하지 마세요.
작업: $ARGUMENTS
관련 파일: (목록) / 코드 구조·콜체인: (사실만) / 영향 범위: (목록)
요청: 단계별 구현 계획, 누락된 영향 범위·리스크, 더 나은 접근.
출력: ## 구현 계획 / ## 리스크 / ## 대안
```

## 출력

메인 분석 → 서브에이전트 피드백 (미사용 시 사유) → 최종 계획 → 리스크
