# 디버깅 독립 조사

1. 메인이 증상·기대 동작·재현 조건을 정리하고 codebase-memory 그래프 도구(`search_graph`, `trace_call_path`, `detect_changes`)로 의심 범위와 가설을 세운다. 원인이 한 파일 안에서 명확하면 서브에이전트 없이 바로 고친다.
2. `Agent`(general-purpose, `model` 생략해 메인 상속, 백그라운드)에게 **사실 정보만** 넘겨 독립 조사를 맡긴다. 메인의 가설은 넘기지 않는다.
3. 양쪽 분석을 종합해 원인을 확정한다. 추가 확인이 필요하면 `SendMessage`로 같은 에이전트에 가장 효율적인 확인 1개를 요청한다.
4. 수정은 메인이 최소 범위로 직접 한다. 재현 절차나 테스트로 검증하고, 기능 변경 수준이면 `/agent-review`.
5. 서브에이전트가 실패하거나 조사가 2회 불충분하면 그 사실을 명시하고 메인 단독으로 전환한다.

## 조사 프롬프트

```
당신은 DmNote(Tauri + React)의 독립 디버거입니다. READ-ONLY: 코드를 수정하지 말고 원인 분석만 보고하세요. 빌드·테스트 실행은 가능합니다.
작업 디렉토리: (절대 경로)
증상: $ARGUMENTS / 기대 동작: ... / 재현 조건: ... / 관련 파일·함수: ... / 최근 변경: ...
요청: 원인 후보와 근거, 재현 가능하면 최소 절차와 직접 검증 결과, 미확정 시 가장 효율적인 추가 확인 1개.
출력: ## 원인 후보 / ## 재현 결과 / ## 추가 확인 필요
```

## 출력

문제 요약 → 원인 → 수정·검증 → 남은 리스크
